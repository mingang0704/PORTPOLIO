# 조민경 포트폴리오

밝은 아이보리·블루 계열의 반응형 홈페이지입니다. 인적 사항, 학력, 영어 성적, 설계/유동/고체·FEM/AI 활용 분류, STAR 상세 보기, 내용 편집기와 비공개 자료실을 포함합니다.

대상 저장소: https://github.com/mingang0704/porfile

## 미리 보기와 내용 수정

`site/index.html`을 브라우저로 열면 홈페이지를 확인할 수 있습니다. `내용 편집`에서 인적 사항, 사진, 학력, 점수, 프로젝트를 수정한 다음 `내용 파일 내보내기`를 누르세요. 다운로드된 `content.js`로 저장소의 `site/content.js`를 교체하고 커밋하면 반영됩니다. 편집 중에는 브라우저를 닫거나 새로고침하지 마세요. 내보내기 전 변경 내용은 자동 저장되지 않습니다.

프로필 사진은 PNG/JPEG/WebP 2MB 이하로 선택할 수 있습니다. 내용 파일에 사진이 포함되므로 별도 이미지 업로드가 필요 없습니다. 성적표나 프로젝트 원본은 공개 소스에 넣지 않습니다.

확인된 정보: 조민경 / 여 / 안산시 상록구 / 010-2608-3992 / mk0704love@naver.com. 양지고등학교 2022.02 졸업, 한양대학교 ERICA CAMPUS 기계공학과 2027.02 졸업 예정. TOEIC Speaking IM3(2026.04.04), NEW TEPS 347(2026.02.28). 요청에 따라 TOEIC 점수와 성적표 항목은 제거했습니다.

경험 8개를 구성했습니다. 기존 4개 경험에 GIST 극초음속 경계층 모델링, FEM 휴대폰 케이스 범퍼 충돌 해석, KDIA PVD 장비 설계·조립, 캡스톤 Gemini 스마트 환기 제어를 추가했습니다. `경험정리.pdf`(6쪽)를 기준으로 STAR와 성과를 재검토하고, 인턴 발표 자료·KDIA 제안서·캡스톤 결과 포스터를 함께 확인했습니다. FEM PDF는 타 연구자의 참고 논문이므로 해당 수치를 본인 성과로 사용하지 않았습니다. 시각 자료는 개념 일러스트로 실제 해석 결과가 아닙니다.

각 프로젝트 카드와 상세 화면에 교과목/기관 및 진행 기간을 표시합니다. 확인된 기간은 GIST 2개월(2026.02.09 최종 발표), 캡스톤 2026년·3개월, KDIA 2026년입니다. 정확한 시작·종료 연월이 없는 항목은 임의로 추정하지 않았습니다. 내용 편집기에서 `교과목 / 기관`, `진행 기간`, `수료증 버튼 이름`을 수정할 수 있습니다. 수료증 이름을 비우면 해당 버튼을 숨깁니다.

자료실의 자료 위치 목록에서 GIST 인턴 수료증과 KDIA 교육 수료증을 각각 선택해 비공개 파일을 등록할 수 있습니다. 수료증은 프로젝트 원본과 별도 위치로 구분되며 동일한 이메일 승인 정책을 적용합니다. 현재 Supabase가 연결되지 않았으므로 파일 업로드·다운로드는 아직 사용할 수 없습니다.

## GitHub Pages 배포

1. 이 폴더의 내용을 `mingang0704/porfile` 저장소 최상위에 넣습니다. `site`, `supabase`, `.github` 폴더 구조를 유지하세요. 특히 숨김 폴더인 `.github/workflows/pages.yml`도 포함해야 합니다.
2. GitHub 저장소 Settings → Pages → Build and deployment → Source를 `GitHub Actions`로 선택합니다.
3. `main` 브랜치로 커밋/푸시하면 포함된 워크플로가 `site` 폴더만 배포합니다. Actions에서 성공 여부를 확인합니다.
4. 예상 주소는 `https://mingang0704.github.io/porfile/`입니다. 실제 배포 성공 전에는 활성 주소로 간주하지 마세요.

빌드나 패키지 설치가 필요 없는 HTML/CSS/JavaScript입니다. Google Fonts 연결이 안 되면 시스템 글꼴로 표시됩니다.

## Supabase 자료실 연결

현재 연결 정보는 비어 있습니다. 홈페이지는 표시되지만 자료실 로그인·파일 등록은 프로젝트 연결 후 사용할 수 있습니다.

1. Supabase에서 새 프로젝트를 생성합니다. 기존 프로젝트에 다른 Storage 접근 정책이 있다면 적용 범위를 검토하세요. 이 구성은 전용 신규 프로젝트를 기준으로 합니다.
2. SQL Editor에서 `supabase/setup.sql`을 **한 번** 실행합니다. 관리자 목록, 승인 요청, 파일 목록, 비공개 버킷과 접근 정책을 만듭니다.
3. Authentication → Providers에서 Email 로그인을 켜고 신규 가입을 허용합니다. 이메일 인증이 켜져 있어야 합니다. 인증되지 않은 사용자는 승인 요청을 등록할 수 없습니다.
4. Authentication → Email Templates에서 Magic Link 메일과 필요한 가입 확인 메일에 `인증번호: {{ .Token }}`을 넣습니다. 이 홈페이지는 링크가 아닌 이메일 인증번호를 입력하는 방식입니다.
5. 실제 외부 방문자에게 메일을 보내려면 Supabase의 사용자 지정 SMTP를 설정합니다. 기본 메일 서비스는 발송 대상과 횟수에 제한이 있으므로 테스트와 운영 발송을 구분하세요. Authentication의 Site URL은 배포 주소로 설정합니다.
6. 프로젝트 URL과 **publishable key 또는 anon key**를 `site/config.js`에 넣습니다. `service_role`, `sb_secret_...`, 데이터베이스 비밀번호를 넣지 마세요.
7. 홈페이지 자료실에서 `mk0704love@naver.com`으로 인증번호 로그인을 완료합니다.
8. SQL Editor에서 `supabase/set-owner.sql`을 실행합니다. 본인 이메일이 1행 출력되면 관리자 등록이 완료된 것입니다. 아무 행도 나오지 않으면 먼저 해당 이메일 인증을 완료하세요.
9. 자료실을 닫았다 다시 열면 관리자 화면이 표시됩니다. 자료 위치와 표시 이름을 정하고 증명서·원본을 업로드합니다. 파일당 최대 50MB이며 큰 CAD/해석 파일은 분할 압축할 수 있습니다.
10. 방문자는 이메일 인증 후 다운로드 권한을 요청합니다. 관리자는 자료실에서 요청 이메일을 확인하고 `승인` 또는 `승인 회수`합니다. 승인 범위는 등록된 자료 전체입니다.

로그인 세션은 현재 탭 메모리에만 보관됩니다. 새로고침하거나 세션이 만료되면 다시 인증합니다. 파일은 공개 링크나 서명 URL을 만들지 않고 인증된 요청으로 내려받습니다. 승인 여부는 다운로드할 때마다 서버 정책으로 검사하며, 승인 회수는 이후 요청부터 적용됩니다. 이미 내려받은 파일의 복사본까지 회수할 수는 없습니다.

## 연결 후 필수 검증

- 로그아웃 상태: 파일 목록과 파일 주소에 직접 접근하면 거부되어야 합니다.
- 인증했지만 미승인인 다른 이메일: 승인 요청만 가능하고 다운로드·업로드·승인은 거부되어야 합니다.
- 해당 계정을 관리자가 승인: 등록된 자료를 내려받을 수 있어야 합니다.
- 승인 회수: 기존 로그인 상태에서도 다음 다운로드 요청이 거부되어야 합니다.
- 미승인 사용자가 직접 API로 요청 상태를 `approved`로 변경하거나 관리자 테이블에 쓰려는 작업도 거부되어야 합니다.
- 관리자: 파일 등록·삭제 및 요청 승인·회수가 가능해야 합니다.

실제 계정·메일·Storage를 사용한 검증은 Supabase 프로젝트 연결 후 수행해야 합니다. 로컬에서 화면이 보인다고 인증이 검증된 것은 아닙니다.

## PDF 기준 재검토

PDF의 경험2~6에 해당하는 기존 프로젝트 5개를 대조했습니다. 핵심 수치는 기존 버전과 일치해 유지하고, 행동·과제·한계 설명을 원문에 맞게 보완했습니다. 상세 대조표는 `PDF-대조결과.md`를 참고하세요. PDF의 봉사활동은 현재 기술 프로젝트 분류에 해당하지 않아 새 항목으로 추가하지 않았습니다. PDF에 없는 인장·충격시험·소성영역 실습 3개는 기존 자료에 근거한 내용으로 유지하고 별도 출처를 표시했습니다.
